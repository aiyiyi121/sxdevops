# AIOps 处置效果验证

## 使用流程

任务草稿生成后，在聊天消息的“处置效果验证”中选择知识环境、当前活跃告警 ID 和观察窗口，保存处置前基线。随后沿用原有确认、载入任务中心、人工编辑和执行流程。

任务中心创建实际任务时，会在开始执行前关联验证记录。现有 `run_aiops_chat_worker` 同时领取效果验证任务；实际任务结束并经过观察窗口后，执行独立的验证图：

```text
范围与权限检查 → 任务执行结果 → 同一告警恢复事件 → 效果判定
```

聊天消息和“智能体审计 → 执行追踪 → 详情”的动作区域均可查看验证状态、处置前后告警状态、关联任务及验证节点记录。点击“查看 / 配置”展开，点击“刷新”读取最新结果。没有提前保存基线的历史任务不会补造处置前事实。

观察窗口默认为任务结束后 60 秒，可设置为 0–600 秒；窗口内不提前判定。当前版本以平台已经接收的告警事件作为证据，不直接连接监控源，不执行任何修复或回滚命令。

## 判定口径

| 状态 | 条件 |
| --- | --- |
| 告警已恢复 | 任务和所有目标的执行记录均成功；同一告警指纹的恢复时间、最近接收时间均在本次任务开始之后，且不晚于当前时间 |
| 验证未通过 | 任务失败、部分成功或跳过目标；或观察窗口结束后告警仍活跃 |
| 证据不足 | 告警缺失、关闭或屏蔽；缺少恢复时间；恢复事件早于任务；告警指纹变化；基线晚于任务；权限、知识环境关联或验证过程中证据发生变化 |

“告警已恢复”只说明在任务开始后观察到该告警的恢复事件，不能证明恢复由本次操作导致，也不能推断业务整体健康。当前版本尚未加入指标持续达标、工作负载就绪或多信号验证。

## 权限与恢复

- 配置和读取接口：`GET/POST /api/aiops/actions/<动作ID>/verification/`，复用 `aiops.chat.analyze` 与 `ops.alert.view`。
- 只有本人原始会话的主机/K8s任务动作可以配置验证。审计人员还需 `aiops.audit.view` 才能读取其他用户的验证；不能代替其他用户配置。所有账号统一检查实际权限，不存在用户名豁免。
- 仅在任务创建前保存活跃告警基线。绑定实际任务时核对本人确认记录、任务创建人和动作来源，验证不提供执行授权。
- 验证范围固定为初始知识环境及其告警环境关联；每个节点、恢复和最终发布结果前重新检查权限及范围。撤权后不输出已保存证据。
- 独立验证图版本为 1，聊天图仍为 12、动作图仍为 1。各阶段使用现有 SQLite/MySQL checkpoint 与节点审计；worker 租约过期后可接管，旧 worker 不得发布结果。
- 已结束的验证 checkpoint 默认保留 30 天，沿用 `AIOPS_LANGGRAPH_RETENTION_DAYS`。worker 空闲清理时删除过期 checkpoint 和节点，保留验证结论；未完成验证阻止相关聊天 checkpoint 提前清理。

## 安装与演示评测

```bash
cd backend
python manage.py migrate
python manage.py seed_aiops_remediation_demo --username admin
python manage.py run_aiops_chat_worker --interval 2
```

演示命令复用已有管理员，不创建账号、不更改密码，也不连接主机或集群。它新增独立的“处置验证演示环境”，生成带 `[演示]` 标识的会话、任务执行记录和告警事件，再由实际验证图处理。重复运行保留已有演示记录并报告结果，不重复造数。

| 样本 | 预期结果 |
| --- | --- |
| 任务成功且收到恢复事件 | 告警已恢复 |
| 任务成功但告警仍活跃 | 验证未通过 |
| 任务失败且告警仍活跃 | 验证未通过 |
| 告警被关闭但没有恢复事件 | 证据不足 |
| 恢复事件早于本次任务 | 证据不足 |
| 原告警证据缺失 | 证据不足 |

评测输出包含每个样本的预期、实际状态和会话 ID。完整回归测试每次在隔离测试库重建样本，并验证断点恢复、租约接管、撤权、环境变化、观察窗口、接口权限与保留清理：

```bash
python manage.py test aiops.test_remediation --noinput
```

这些构造样本验证流程与判定边界，不代表真实生产故障修复成功率。未来可在相同证据格式下补入脱敏的真实故障基准。
