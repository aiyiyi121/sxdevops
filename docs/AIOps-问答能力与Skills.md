# AIOps 问答类型与 Skills

问答类型是用户选择的任务入口，Skill 是可复用的专业方法包，工具负责实际查询和操作。聊天问答类型、智能体配置和审计使用同一份服务端目录。

```text
自动识别或用户选定问答类型
  → 确认环境、上下文与权限
  → 加载该能力挂载且用户可用的 Skills
  → 由运行流程调用允许的 MCP / 平台工具
  → 输出证据、结论或待确认操作
```

## 统一能力目录

| 问答类型 | 标识 | 主要职责 | 环境预选 |
| --- | --- | --- | --- |
| 故障排查 | `troubleshoot` | 异常取证、根因分析、K8s 诊断和恢复建议 | 需要 |
| 日志查询 | `log.query_generate` | 日志查询生成、检索和异常模式分析 | 需要 |
| SLO 评估 | `slo.analysis` | 可用性、延迟、错误率和目标风险评估 | 需要 |
| 事件分析 | `event.analysis` | 事件、发布、变更、工单和告警时间线关联及影响分析 | 需要 |
| 任务生成 | `host_task.generate` | 主机、Playbook 和 K8s 任务草稿 | 需要 |
| CMDB | `cmdb` | 资产、成本、依赖拓扑和数据质量 | 按 CMDB 资源授权查询 |

“自动识别”是路由方式，不是额外的能力。事件分析回答发生了什么、如何关联及影响哪些对象；故障排查回答异常原因和恢复路径，二者可以复用事件、可观测性和安全处置方法。

## 十三个内置 Skill

将重复的查询规范合并，同时保留告警、指标、链路、系统态势和安全边界等独立专业方法。下表是出厂挂载关系，管理员可在问答类型中调整。

| Skill | 标识 | 整合范围 | 默认复用能力 |
| --- | --- | --- | --- |
| 统一应答规范 | `answer-formatter` | 事实、推断、证据、风险和输出规范 | 全部六项 |
| 告警证据分析 | `sx-alert-evidence` | 告警状态、根因候选和影响证据 | 故障排查、SLO 评估、事件分析 |
| 指标与 SLO 分析 | `sx-metric-slo-analysis` | 可用性、延迟、错误率和资源指标 | 故障排查、SLO 评估、事件分析 |
| 链路证据分析 | `sx-trace-evidence` | 调用链、服务依赖和请求跨度 | 故障排查、SLO 评估、事件分析 |
| 系统态势分析 | `sx-system-posture` | 系统、服务、主机和资源整体状态 | 故障排查、SLO 评估、事件分析 |
| 日志查询与分析 | `sx-log-analysis` | 查询生成、字段映射、日志样本和模式分析 | 故障排查、日志查询 |
| K8s 诊断与取证 | `sx-k8s-diagnostics` | 集群告警、工作负载、Pod 和 Event 取证 | 故障排查 |
| 事件关联与影响分析 | `sx-event-analysis` | 变更影响、事件时间线和关联置信度 | 故障排查、事件分析、SLO 评估 |
| 容器操作安全护栏 | `sx-container-safety-guard` | K8s/容器只读取证和写操作确认边界 | 故障排查、任务生成 |
| 自愈风险评估 | `sx-self-heal-safety` | 自愈适用条件、风险、dry-run 和回滚 | 故障排查 |
| 任务模板编排 | `sx-task-template-selection` | 按资源、环境和风险选择任务模板 | 任务生成 |
| 回滚策略评估 | `sx-rollback-strategy` | 变更影响、验证证据和停止条件 | 故障排查、事件分析 |
| CMDB 资产与成本分析 | `sx-cmdb-asset-cost-analysis` | 资产、成本、拓扑及数据质量 | CMDB |

任务入口不再单独提供 K8s 诊断或自愈建议，故障排查根据问题选择专业处理流程。Skill 不应为了一个提示词或一条查询拆成独立包，只有存在独立专业方法、维护边界或权限边界时才新增。

## 挂载关系与管理

- 能力侧是唯一编辑入口：`PATCH /api/aiops/admin/capabilities/<code>/` 接收 `{ "skills": ["slug"] }`，需要 `aiops.config.manage`。
- Skill 页只展示反向归属，不能另行编辑“适用 Action”。数据库沿用 `AIOpsSkill.applicable_actions` 存储规范化的能力标识，以兼容既有数据结构。
- 智能体策略的“能力范围”选择问答类型，默认开放六类；清空并保存后暂停处理问答。停用类型同时影响聊天、自动路由和外部 A2A 任务，旧动作编码也遵循同一限制。
- MCP 和 Skill 以各自页面的启用开关为准，策略不再重复筛选。Skill 仍需挂载到相应问答类型并满足适用角色；挂载不会绕过工具权限、环境边界、操作确认或执行策略。
- 停用的 Skill 可保留挂载，管理页标明停用状态，运行时不加载。
- 自定义 Skill 可被不同能力复用，不会被内置目录自动覆盖。

### MCP 关联

MCP Server 是工具的唯一配置入口，问答类型和 Skill 只根据各自声明的工具依赖自动展示反向关联，不再维护第二套手工绑定。管理接口会返回 `mcp_server_names` 和 `mcp_bindings`，其中每条绑定包含工具名、Server、启用状态和 Server 类型；同一个工具可以由多个 Server 提供。运行时仍以启用的 MCP、工具白名单、用户权限和问答类型安全策略共同决定是否可调用。

典型关联如下：

| 工具范围 | MCP Server | 使用方 |
| --- | --- | --- |
| 告警、指标、日志、链路和系统态势 | 可观测性 MCP | 告警证据、指标/SLO、日志、链路、系统态势等 Skill |
| 环境、服务依赖和主机关系 | 知识图谱 MCP | 需要知识图谱环境的问答类型和多数取证 Skill |
| 事件墙和最近变更 | 时间中心 MCP | 事件关联、回滚策略和故障排查 |
| 工单状态 | 工单系统 MCP | 事件分析 |
| 任务资源和任务草稿 | 任务中心 MCP | 任务模板、自愈风险和任务生成 |
| 集群、K8s 资源和容器资产 | 容器管理 MCP | K8s 诊断、容器安全护栏 |
| CMDB 资产、成本、拓扑和质量 | CMDB 资产 MCP | CMDB 资产与成本分析 |

## 迁移与兼容

旧入口 `alert.root_cause`、`k8s.diagnose`、`self_heal.recommend` 规范化为 `troubleshoot`；`change.correlation` 规范化为 `event.analysis`。旧会话、外部任务和审计的标识继续兼容，内部专业处理流程保留原标识用于执行路由和历史追溯。

内置 Skill 合并采用版本化迁移，旧源记录通过 `merged_into` 归档并保留内容，默认管理列表和运行时均不再加载归档项。已有定制方法内容和输出约束保留：原组存在停用项时，新包保持停用；角色范围取交集，交集为空时停用。升级后应核对 Skill 启用状态和适用角色。

策略通过 `enabled_capability_codes` 保存开放的问答类型。旧字段 `enabled_mcp_server_ids` 和 `enabled_skill_ids` 暂保留为只读兼容字段，不再参与运行时筛选。

“问答类型”与实际执行操作分开：类型只定义入口和流程；写操作仍形成待确认操作，经服务端权限、风险检查和确认后执行。`AIOpsPendingAction` 的执行含义保持不变。
