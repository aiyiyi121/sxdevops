# 账号、RBAC 与安全

本文描述当前授权与部署边界。版本变更和验证结果分别见 [v2.0.0 更新说明](releases/v2.0.0.md)和[验证记录](releases/v2.0.0-validation.md)。

## 授权模型

有效权限来自用户直接角色与用户组继承角色的并集，并受功能开关过滤；停用账号没有有效权限。后端检查是执行边界，菜单、路由和按钮只反映服务端能力。

权限实现入口为 `backend/rbac/registry.py`、`services.py` 和 `permissions.py`。新接口或 action 必须明确配置权限，未配置的 ViewSet action 默认拒绝。模块可见性、数据范围和操作权限分别检查，能进入页面不代表能读取全部数据或执行写操作。

## 用户、角色与用户组

在“系统管理 → 用户管理”中维护身份、角色、用户组及 K8s 范围。查看、管理和权限字典同步分别授权：

| 权限 | 含义 |
| --- | --- |
| `rbac.user.view` / `rbac.user.manage` | 用户查询 / 管理 |
| `rbac.role.view` / `rbac.role.manage` | 角色查询 / 管理 |
| `rbac.group.view` / `rbac.group.manage` | 用户组查询 / 管理 |
| `rbac.permission.view` / `rbac.permission.sync` | 查看权限字典 / 同步目录 |

- 委派管理员只能管理已分配权限不超过自己的账号、角色和用户组；同时检查变更前状态，不能先降权再接管账号。
- 普通管理员不能通过账号 API 修改、停用、删除或重置超级管理员、Django staff 的密码；API 不允许提升 staff、superuser 身份或修改用户名。
- 共享角色变更检查直接成员和经用户组继承的成员，成员增删也检查受影响账号，防止间接改动受保护身份。
- 内置角色只读，可复制后建立自定义角色；内置编码保留，不能由自定义角色占用。
- 禁止停用或删除当前登录账号，以及最后一个启用的超级管理员。
- 停用用户或修改密码会撤销 DRF Token 和数据库登录会话；重新启用不会恢复旧 Token。密码校验包含目标用户信息，保留首尾空格。
- 授权变更记录前后关系并在事务中保存；审计权限与业务管理权限分开分配。

Django 管理站点、数据库和服务器权限由独立的运维边界控制，不能仅凭平台角色推断其安全性。

## 敏感能力与资源范围

| 能力 | 额外边界 |
| --- | --- |
| Kubernetes | 平台能力与集群、命名空间、集群角色及 Pod 终端策略共同生效；任务中心和 AIOps 同样检查 |
| K8s Secret 内容 | 另需 `ops.k8s.secret.view`；平台管理员和运维管理员默认拥有，开发者和只读角色不默认拥有 |
| 终端与命令 | SSH、Docker、Pod exec、kubectl 和集群 Shell 具有实际执行能力，应单独授权 |
| 云资源写入 CMDB | 云同步权限之外还需 `cmdb.ci.manage` |
| 告警 Webhook | 所有集成类型，包括 generic，都必须携带有效的启用集成 Token |
| AI 审计 | 查看使用 `aiops.audit.view`，管理删除使用 `aiops.audit.manage`；不开放审计记录创建入口 |

只拥有 `ops.task.execute` 不能绕过 K8s 的具体操作权限。Secret 内容权限也不限制已经授予的 exec、kubectl 或集群终端能力，这些能力本身可以访问集群内敏感数据。完整范围规则见 [K8s 工作台](K8s工作台与用户授权.md)。

只读配置接口遮蔽 MCP 认证、命令/地址、告警 Token / Webhook、通知配置及嵌套数据源凭据；管理接口保留必要编辑能力。审计对常见凭据字段脱敏，但历史已保存记录不会自动重写，公开数据前仍需核查历史内容和外部凭据。

## 初始化与旧账号升级

平台没有固定默认密码。使用 `createsuperuser` 创建管理员，或在首次迁移前设置 `SXDEVOPS_ADMIN_INITIAL_PASSWORD`；登录请求不创建管理员，也不隐式同步内置角色。

`seed_data` 只导入业务演示数据。显式角色测试命令 `seed_rbac_demo` 及密码行为见[快速开始](getting-started.md#演示数据与测试角色)，不应在公开服务中运行。

迁移 `rbac.0013_remove_legacy_demo_accounts` 会撤销旧 `demo`、`demo_ai` 的 Token 和会话，删除账号、成员绑定及所属聊天副本；保留其他用户、管理员原始聊天、共享角色、权限目录和独立审计事件。反向迁移不会恢复被删账号或聊天，升级前应备份数据库。后续手动创建同名用户不会获得用户名特权。

若需清理指定用户的新会话，使用 `cleanup_aiops_new_sessions --username <user> --dry-run` 先预览，再明确决定是否执行，不能省略目标用户。

## 登录与连接边界

- 登录受 IP 与账号双层限流保护，依赖 Django cache；多实例使用共享缓存，并在可信网关规范转发客户端 IP。
- 登录目标仅允许有权访问的站内页面；无权访问默认页时回退到可访问页，无可访问页面时返回 403。
- Token 撤销和账号停用阻止后续 HTTP 与新建 WebSocket；当前不会主动切断已经建立的终端连接。
- 账号泄露时还需关闭已有连接、核对执行记录并轮换相关外部凭据；已发出的工具请求无法通过撤权自动撤销。

## 公开介绍与只读演示

产品介绍可以公开展示功能与脱敏截图。在线演示使用独立数据、独立凭据和隔离网络；不要连接生产主机、集群、云账号或真实模型密钥。

为访客建立专用自定义角色，只给实际展示所需的查看权限，并复核其可读范围。不要直接复用 `ops_demo` 或把内置“只读”名称当作数据已经脱敏的保证。终端、命令、配置管理、任务执行、Secret 内容、授权管理及公开写入接入均应在服务端关闭或拒绝。

生产管理入口与演示入口分别保护。域名或子域名变化不会清除应用漏洞，也不能保证原域或新域的安全信誉。

## 站点安全告警处理

Chrome 危险网站提示可能来自 Safe Browsing；应先确认提示类型并检查 Search Console 的“安全问题”和 Google 透明度报告中的站点状态，不能仅凭截图断定根因。

检查线上文件、异常账号、访问日志、注入脚本、外链/下载和第三方资源，处理入侵来源并轮换受影响凭据。确认访问路径已干净后，按 Google 提供的入口提交复审，说明发现的问题和整改证据。审核时间取决于问题和复查结果，没有本项目能保证的完成时限。

本项目的权限修复不会自动解除浏览器警告。新子域也不能替代服务器清理、内容核查和信誉复审。

安全漏洞反馈见 [SECURITY.md](../SECURITY.md)。
