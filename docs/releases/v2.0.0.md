# SxDevOps v2.0.0 版本更新说明

本文记录 `v2.0.0` 的功能变化与升级要求，可用于 GitHub Release。发行源码以 `refs/tags/v2.0.0` 为准；最近核对的提交、部署结果与已知限制见[版本验证记录](v2.0.0-validation.md)。

## 本版重点

v2 将 CMDB 资产底座、LangGraph 智能体、任务执行及 Kubernetes / Docker 工作台进一步衔接。平台版本为 `v2.0.0`；聊天图 `12`、动作图 `1` 和处置验证图 `1` 分别用于内部流程兼容检查。

## CMDB 与任务资源

### 统一资产入口

- 统一资产概览、资源搜索、台账、视图、同步、模型、成本与治理入口，按业务线和环境组织资源。
- 通过模板接入云资源、vSphere、机房服务器及第三方服务；凭据按既有安全配置维护。
- CMDB 页面复用统一平台页头，资产视图与分类拓扑保持一致的导航上下文。

### 显式接入执行资源

- 任务资源支持从 CMDB 选择主机、虚拟机或 K8s 资产，也可手工添加；选择后取消不创建资源，每项 CMDB 资产最多接入一次。
- 复用 CMDB 的有效基础字段和归属；缺失字段可在任务资源中补充，执行密码单独维护，不导出 CMDB 登录密码。
- 已接入资源随源资产更新基础信息与资源树名称；CMDB 后续补齐的字段优先于本地补充值。
- 资产停机、下线或关联失效时阻止新的任务执行。移除执行资源保留源资产，现有手工资源与历史任务引用不自动迁移。
- 选择器与资源列表支持业务线/环境树、来源筛选和分页，读取遵守 CMDB 范围授权，接入同时检查任务资源管理与资产查看权限。

### 指标与拓扑

- 水位、资产详情及治理从数据库选取每项资产、每类指标的最新快照，避免为了去重在应用内存加载大量历史记录。
- 最近 14 天 CPU / 内存均值改为数据库聚合，资产合并时指标归属批量更新。
- 拓扑支持仅命中节点和最多三跳邻居；限定授权资产，展示命中节点之间的关系，图例随实际节点和边类型变化。

操作与边界见 [CMDB 使用手册](../CMDB使用手册.md)及[任务资源接入说明](../task-resource-cmdb.md)。

## AIOps 与 LangGraph

### 持久化编排

- 默认聊天接入 LangGraph。单条告警、K8s 异常、服务异常、环境告警、变更关联、自愈推荐与 SLO 分析均按证据阶段保存 checkpoint。
- 通用工具调用拆为模型规划、单次工具执行和结果汇总；任务生成拆为范围、资源、草稿及汇总；模型回复整形拆为准备、调用、检查、有界修复、兜底和最终输出。
- 数据库队列由独立 worker 消费，支持过期租约接管；已完成且保存 checkpoint 的阶段可复用，恢复时重新检查身份、工具权限与原始范围。
- 默认本地 SQLite checkpoint；Compose 使用共享 MySQL checkpoint。节点内中断仍可能重试当前请求，外部工具需满足幂等要求。
- 对平台允许的只读临时连接错误进行有界重试；权限拒绝、写操作和外部 MCP 不自动重试。节点记录时间预算与失败原因，预算不能撤销已经发出的调用。

### 输出、策略与审计

- 默认问答入口整理为故障排查、日志查询、SLO 评估、事件分析、任务生成和 CMDB 六类。
- 十三个内置可复用 Skill 统一专业方法，能力侧维护挂载；MCP Server 是工具配置入口，能力和 Skill 自动展示工具依赖及 Server 关联。
- 回复按对象与语句核对事实，减少把其他证据的数量误判为告警矛盾；SLO 没有明确目标时不自行定义达标阈值或错误预算。
- 关键动作继续由 Django 执行权限检查、预检和本人确认。动作图的检查、人工等待和执行分开记录，不把人工等待计作执行耗时。
- 执行追踪按本轮消息关联节点、工具、模型和动作，显示失败、重试、恢复、worker、checkpoint 与图版本；错误脱敏，不向接口暴露完整 checkpoint 或租约令牌。
- 框架依赖不可用时明确显示兼容降级与恢复限制；普通运行异常不触发无提示的兼容重跑。完成且过期的 checkpoint 按保留规则清理，保留会话正文与结论。
- 会话历史缩小标题最小宽度、加宽操作列，并固定执行追踪与删除按钮同一行。

### 处置效果验证

```text
执行前保存活跃告警基线 → 关联实际任务 → 等待任务结束及观察窗口
  → 范围与权限检查 → 任务执行结果 → 同一告警恢复事件 → 效果判定
```

- 任务中心开始执行前绑定验证，默认在任务结束 60 秒后取证，可配置 0–600 秒。
- 全部目标执行成功且收到同一告警在任务开始后的有效恢复事件，才显示“告警已恢复”。
- 任务未全部成功或告警仍活跃显示“验证未通过”；关闭、屏蔽、丢失或时间不符等证据显示“证据不足”。
- 聊天和执行详情展示基线、任务结果、目标成功数、告警状态及验证节点；六组明确标记的模拟演示可重复评测。
- 结果不证明处置因果，也不代表业务整体健康；当前尚未覆盖指标持续达标、工作负载就绪和多信号验证。

详见 [LangGraph 运行说明](../AIOps-LangGraph-试点说明.md)、[问答能力与 Skills](../AIOps-问答能力与Skills.md)、[处置效果验证](../AIOps-处置效果验证.md)。

## 容器管理

### Kubernetes

- 扩展网络、存储、配置与 HPA、ResourceQuota、LimitRange 等资源管理；按当前资源类型和命名空间提供 YAML 模板。
- YAML 单资源创建/编辑先进行 Kubernetes dry-run 和差异确认，更新检查 resourceVersion；删除、重启、CronJob 暂停及节点调度等操作沿用权限与确认。
- 平台角色权限叠加用户集群、命名空间和 Pod 终端授权；命名空间受限用户不展示整集群资源与容量，API、WebSocket、AIOps 和任务执行统一检查范围。
- 容量表展示实际用量、Requests、Limits、可分配及总容量，汇总 init 容器、sidecar 与 Pod overhead；缺少或无权读取 metrics 时显示不可用。
- 列表默认每页 50 条，行菜单按需挂载；并发查询、上下文内请求合并、短缓存与过期结果隔离减少切换和刷新开销。
- 集群与 Pod 终端支持 Shell、全屏、重连、复制粘贴和会话下载，Tab 交由实际 Shell；集群 Bash 加载 kubectl 补全，Pod 使用容器已有环境。
- Pod 日志首屏最近 500 行，通过签名游标双向翻页；客户端最多保留三页，服务端临时文件有容量与过期限制，展示原始日志。

### Docker

- 环境卡片与概要、容器和镜像列表共用紧凑工作台，显示版本、系统、架构、容量及资源数量。
- 列表默认每页 20 条，支持搜索、状态筛选、环境切换与手动/定时刷新；弹窗或后台页面暂停自动刷新，旧环境响应不覆盖新环境。
- 启停、重启、删除及镜像清理前明确目标并确认；镜像按 ID 去重，不强制删除被容器使用的镜像。
- 容器详情支持 JSON 复制及全屏；历史日志复用分页窗口，运行中容器支持交互终端与 Shell 选择。
- 终端固定进入目标容器，查看、管理、终端权限分开校验；关闭窗口回收 WebSocket、SSH 与观察器。
- 环境概要及列表采用短缓存，手动刷新绕过缓存；SSH 同时读取标准输出和错误输出，并限制大小、超时和连接生命周期。

详见 [K8s 工作台与用户授权](../K8s工作台与用户授权.md)及[Docker 工作台](../Docker工作台.md)。

## UI 与系统设置

- 新增浅色、炭灰、深蓝灰三套主题。首次访问使用浅色，炭灰为推荐深色方案；左侧菜单底部切换并记住选择，图标对应当前主题。
- 深色主题覆盖卡片、列表、表单、弹窗、代码及图表，统一文字对比度与状态色；移除智能助手输入框多余的内部框线。
- 移除顶部导航，将工具入口收纳到侧栏底部；优化侧栏标题、收拢标题和右侧圆角，与工作台 hero 保持一致。
- 智能助手、知识图谱、K8s 等页面及列表卡片适配可用高度，减少短内容页面底部留空。
- 「模块管理」更名为「系统设置」，统一提供基础配置与菜单管理。网站名称最多 10 个字符，支持上传 PNG、JPG、WebP、ICO 图标及恢复默认；保存后更新侧栏、登录页、浏览器标题与图标。
- 菜单支持排序、显示和默认页面，待完善页面默认隐藏，RUM 使用简短标题；配置写入沿用管理权限与操作审计，所有账号统一按实际 RBAC 校验。

详见 [主题说明](../frontend-theme.md)。

## 账号与权限加固

- 移除旧 `demo`、`demo_ai` 账号和用户名特权，演示业务数据初始化不再创建登录账号。
- 收紧委派管理员、共享角色、用户组及受保护身份的变更边界，密码修改和停用撤销 Token 与登录会话。
- 增加独立权限字典同步和 K8s Secret 内容权限，任务执行复查具体 K8s 能力及资源范围。
- generic 告警 Webhook 也需有效 Token；只读配置和审计记录遮蔽敏感字段，关闭意外审计创建入口。
- 菜单、登录落点、路由与功能开关对齐，权限拒绝不返回默认健康结果。

升级兼容与存量连接限制见[账号、RBAC 与安全](../user-permission-security.md)。

## 其他调整

- 项目开源协议调整为 MIT，新增根目录 `LICENSE`，README 与前端包元数据同步，应用镜像保留 `/app/LICENSE`；第三方依赖继续遵循各自许可。
- 前端包与锁文件版本统一为 `2.0.0`，停止跟踪本地运行日志。
- 统一工作台的页头、卡片、页签、筛选、列表和弹窗密度，菜单排序可在系统设置中配置。
- 模块可见性继续叠加账号权限，前端展示与后端执行边界一致。
- 补充部署、运行、验收及演示文档；README 更新为当前本地产品的真实截图。

## 升级与已知边界

- 需更新后端依赖、执行全部数据库迁移，并使应用、CMDB 调度器和 AIOps worker 使用同一发行镜像。
- 升级前排空活动聊天与实际任务，并处理未完成验证和待确认动作；未完成旧图 checkpoint 不保证跨图版本恢复。
- 保留数据库、checkpoint 与 `CMDB_PASSWORD_ENCRYPTION_KEY`；Kubernetes 基础清单需额外补充 AIOps worker。
- 最近后端全量执行 906 项，46 项失败、7 项错误，均为已知失败名称；全库未通过。专项通过和实际部署检查见验证记录，不能代替完整质量结论。

完整流程见 [v2.0.0 升级与发布指南](v2.0.0-release-guide.md)，本次通过项与验证限制见 [源码发行验证记录](v2.0.0-validation.md)。
