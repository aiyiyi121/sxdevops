## PostgreSQL 默认部署调整（2026-10-30）

- 新部署默认 PostgreSQL 16，Compose、Kubernetes、一键启动脚本、配置示例与共享 checkpoint 已同步；MySQL 8 使用独立备选清单。已有部署保留原数据库，禁止通过部署参数直接转换数据库类型。
- Windows 上使用一次性隔离的 PostgreSQL 16.4 实例完成全套 Django 建库迁移及定向测试，覆盖原生连接、库列表发现、工单 DML / DDL、失败回滚、中文及 dollar quote、只读查询和 LangGraph checkpoint 读写。新增的完整数据源创建 → 工单审核执行 → 查询 API 用例通过。
- SQLite 定向回归、PostgreSQL 配置默认值、MySQL 备选配置、旧数据源类型更正及自定义连接保留检查通过；本地平台仍使用 SQLite，没有搬迁到 PostgreSQL。浏览器检查 PostgreSQL 表单的 `5432` 端口、用户名、连接库、UTF8 及浅色 / 炭灰 / 深蓝灰主题，已恢复原主题。
- Kubernetes 安装器 16 项测试通过；PostgreSQL / MySQL 两套清单的 ConfigMap、Secret 引用及三个应用服务配置一致性检查通过。两种启动脚本的 8 项模拟场景通过；前端生产构建、迁移一致性、UTF-8 与差异检查通过。
- 未连接业务数据库或真实 Kubernetes 集群；尚未构建并运行 Docker 镜像，MySQL 备选未进行真实实例验收。此前全量 SQLite 回归记录见下文，不将其视为本次 PostgreSQL 的全量回归。

## 后续修复验证

- 修复 CMDB 文字业务范围被清空、后台写入后的汇总缓存失效问题，以及 AIOps 资源查询误判为变更关联/自愈、旧环境筛选遗漏等缺陷。过期测试按当前资源类型、元数据和资产开关行为更新；保留现有 v2 功能语义。IaC 测试使用独立路由，产品已退役入口仍保持 404。
- 四类终端加入连接前、每次输入和空闲期间的权限复核与主动关闭。登录计数改为缓存原子操作，Compose/Kubernetes 配置共享 Redis 和明确的可信代理列表；缓存故障拒绝登录。
- Kubernetes 补齐 AIOps worker、共享 MySQL checkpoint、应用密钥和 schema 等待；13 个对象通过严格 Kubernetes 1.29 schema 校验及服务选择器、镜像、Secret 和后台进程配置一致性检查。Compose 配置不变量通过检查；本机没有容器引擎或真实集群，尚未构建镜像或运行集群验收。
- 处置验证增加可选 API 指标和关联告警策略、处置前后采样证据及保守的缺失数据判定；因果字段明确为时间关联，不声称已实现因果证明。前端仍为默认告警验证编辑器，使用方法见[处置效果验证](../AIOps-处置效果验证.md)。
- Django 系统检查、全局 `makemigrations --check --dry-run` 及全新隔离数据库完整迁移通过。前端生产构建通过，88 个生产包的许可文本随静态发行文件生成。
- 完整后端复测 **927 项全部通过，0 失败、0 错误，耗时 839.639 秒**。此前 62 项定向复测与全量有重叠，不重复累计。首轮失败与后续结果的区别见下方历史记录。
- 变更 Python 语法、UTF-8、新增乱码和差异空白检查通过。前端仍有现存 PostCSS `from` 参数警告，构建成功；不将构建成功视为所有真实集成验收完成。
- 历史凭据、候选源码和依赖许可的核对结果见[安全与依赖核对](v2.0.0-security-review.md)。实际环境的旧密钥轮换和 GitHub 私密报告启用仍需对应管理员完成。

后端使用 Windows、Python 3.14.6、Django 6.0.7，内存 SQLite、本地缓存/Channels 与快速测试密码哈希；没有连接业务数据库、真实 Redis、主机或集群。此结果不能代替 Linux、MySQL、真实终端资源清理和多进程 Redis 的部署验收。本轮没有升级实际数据库或部署服务器；公网站点问题按用户要求暂缓，待全新部署后处理。
