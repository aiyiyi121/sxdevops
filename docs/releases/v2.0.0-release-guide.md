# v2.0.0 升级说明

本说明针对已有环境升级到 v2.0.0。首次安装见[快速开始](../getting-started.md)，通用备份、镜像更新与回退见[部署与运维](../deployment.md)。正式源码标签为 `refs/tags/v2.0.0`，最近核对的发行提交与验证限制见[验证记录](v2.0.0-validation.md)。

## 升级前确认

1. 停止接收新任务，处理活动聊天、实际任务、待确认动作与未完成验证。当前聊天图为 12、动作图为 1、验证图为 1，旧的未完成 checkpoint 不保证跨图版本恢复。
2. 备份数据库、checkpoint、运行卷、私有配置和当前镜像摘要；沿用原 `CMDB_PASSWORD_ENCRYPTION_KEY`。
3. 让应用、CMDB 调度器和 AIOps worker 使用同一发行镜像；应用和 worker 共用 MySQL checkpoint。切换 checkpoint 后端不会自动迁移未完成状态。
4. 关闭业务演示数据初始化；模板同步按实际变更独立评估，不要覆盖已有业务数据。

## 数据库与账号变化

执行完整 `python manage.py migrate --noinput`，不要只执行某一条迁移。迁移涉及聊天队列、节点审计、能力目录、处置验证、CMDB 执行资源关联、K8s 用户范围及权限同步。

本仓库的 v2 源码以原 v2 开发快照为基线。旧 `sxdevops/main` 的 `aiops.0021_remove_aiopsknowledgeenvironment_posture_environments`、`ops.0057_delete_system_posture_models` 和 `ops.0058_taskresourcegroup_event_environment` 与该基线的迁移历史不同。已应用这些旧迁移的环境，须先在数据库副本上核对实际表结构和迁移记录，完成专项升级演练；本次源码同步只验证了全新数据库安装，不能据此保证旧分支可直接执行 `migrate` 升级，也不要直接使用 `--fake` 跳过差异。

公开源码保留迁移名称、依赖与表结构操作，移除了历史迁移内的实际资产、环境和软件清单。新安装不会自动导入这些私有业务数据，已有数据库中的业务数据不会因此删除；实际资源通过平台正常接入流程维护。

`rbac.0013_remove_legacy_demo_accounts` 删除旧 `demo`、`demo_ai` 账号、Token、会话及其聊天副本；管理员原始聊天、其他用户和共享角色保留。该数据清理不可通过反向迁移恢复。所有用户名特权已移除，同名新用户也必须按普通 RBAC 授权。

`seed_data` 不再创建账号；`seed_rbac_demo` 仅显式维护隔离环境中的角色测试账号，未设密码时生成随机值但不输出。没有管理员时使用 `createsuperuser`，不要继续依赖旧演示登录。

## 授权与接入兼容

- 普通管理员只能管理授权范围不超过自己的账号、角色与用户组，不能接管 superuser / staff；修改共享角色还检查间接成员。现有委派管理员可能无法继续管理部分账号，应由超管配置适当自定义角色。
- 同步权限字典另需 `rbac.permission.sync`，不再由查看权限执行。
- K8s Secret 内容另需 `ops.k8s.secret.view`。已有自定义角色需要读取内容时应显式授权；普通查看仍可读取元数据。
- K8s 任务执行同时检查具体平台能力与资源范围，只有任务执行权限不再足够。
- 所有告警 Webhook，包括 generic，必须配置启用集成的有效 Token，旧匿名调用方需调整。
- 云资源批量同步至 CMDB 另需资产管理权限；只读配置响应遮蔽敏感字段，调用方不能依赖明文凭据回传。
- 六类问答入口与旧动作编码保持规范化兼容；内置 Skill 合并后应核对启用状态、适用角色与挂载关系，见[能力目录](../AIOps-问答能力与Skills.md#迁移与兼容)。

完整边界见[账号、RBAC 与安全](../user-permission-security.md)。已经保存的历史敏感审计不会自动清洗；已有 WebSocket 也不会因撤权自动断开，需分别处理。

## 部署要点

Compose 已包含两个后台服务。按[运维步骤](../deployment.md#备份与升级)备份、迁移并显式重建三项应用容器；重建镜像后还要确认运行容器实际使用新镜像。

Kubernetes 基础清单尚未定义 AIOps worker，也未配置共享 MySQL checkpoint。启用完整异步聊天及处置验证前，按 [Kubernetes 部署指南](../Kubernetes部署指南.md#aiops-worker-与共享-checkpoint)补齐 worker、共享配置和必要密钥。

## 升级后验证

- 三项应用服务使用同一镜像；数据库迁移完整，无自动演示账号或业务造数。
- 最小权限账号的菜单、接口、资源范围及拒绝结果符合预期；检查 Secret 内容和终端入口。
- CMDB 定时采集、任务资源关联、异步聊天、执行追踪和 checkpoint 正常。
- 使用明确测试资源验证动作确认及效果验证；构造样本不能当作生产故障修复成功率。
- 凭据、历史数据和站点安全提示独立核查，不能把一次代码部署当作 Google 安全警告已解除。

回退时一并评估数据库与 checkpoint 兼容性，按[回退说明](../deployment.md#回退)操作。后续补丁使用新版本标签，不覆盖已发布标签。
